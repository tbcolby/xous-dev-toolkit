# Slice report: `emulators-othello`

Repos audited: `precursor-othello` (pkg `othello` + `libs/othello-core`), `precursor-c64` (pkg `c64`), `precursor-gameboy` (pkg `gameboy`).
Every `.rs` file in the three repos was read. Source repos were not modified.

Paths below are relative to `SCRATCH/precursor/<repo>/` unless noted. SCRATCH = `/private/tmp/claude-501/-/222625fb-1cb9-475b-aba1-974303a9b50f/scratchpad`.

## How findings were verified

Besides reading the code, three host-side harnesses were built under `SCRATCH/work-eo/` (copies only):

| Harness | What it ran | Result |
|---|---|---|
| `work-eo/othello-core` (copy of `libs/othello-core`) | `cargo test` as shipped | **40/40 pass on host** (needs network once: an unused `rand` dev-dependency must be downloaded) |
| same, `tests/audit.rs` (added in the copy) | Differential test of `calculate_flips` against a naive row/col reference over 2,000 random playouts; perft 1-9; opening-book probe; AI timing | Engine is **wrong in 76.4% of positions**; perft diverges at depth 5; book never hits; see Othello section |
| `work-eo/cpu6502` (copy of c64 `cpu.rs`) | Klaus Dormann `6502_functional_test.bin`; exhaustive BCD ADC/SBC vs NMOS reference; legal-opcode coverage; illegal-opcode length | **Functional test passes** (success trap `$3469`, 30.6M instructions); 151/151 legal opcodes present; BCD accumulator + carry exact; minor flag deviations |
| `work-eo/gbcpu` (copy of gameboy `cpu.rs`) | Ran the four built-in demos to halt | 2 of 4 demos are wrong (one never halts) |

Screenshots shipped in the repos were also inspected, because they turned out to be evidence:
- All five `precursor-c64/screenshots/*.png` (`menu`, `menu_boot`, `running`, `import_wait`, `menu_return`) show the **Xous Shellchat screen ("Please wait...")**, not the emulator. The README captions them as the C64 menu / BASIC prompt.

Items marked **Suspected** were not reproduced, only reasoned from code.

# 1. Othello (`precursor-othello`)

**Verdict:** Nicely structured (pure-logic core crate + thin Xous shell, 40 host tests), but the shipped build is not playable: the move generator is wrong at the board edges, the AI is never invoked, F-keys are bound to the wrong codepoints, and all persistence/TRNG/haptics are compiled out on the real target. **Health: 3/10.**

### Test quality (othello-core)
Tests do run on host and all pass, but several are vacuous and that is why O-1 survived: `ai.rs:431-446 test_corner_preference` wraps its only assertion in `if calculate_flips(.., 0) != 0` (which is false *because of* O-1); `moves.rs:255-271 test_multiple_direction_flip` asserts 0 flips twice; `ai.rs:449-466 test_endgame` and `opening.rs:147-152` assert nothing. No test places a disc on an edge. `rand` is declared as a dev-dependency but never used; it only makes `cargo test --offline` fail.

## Upstream drift
One error: `src/main.rs:161` `xous::destroy_server` is now `unsafe` (wrap in `unsafe {}` or drop the call before `terminate_process`). Everything else already matches current GAM (`isize` points, `String` app name). Packaging: `Cargo.toml` expects `../../libs/othello-core` but the repo ships it at `./libs/othello-core`; the README documents the manual copy, a git submodule or publishing the crate would be more robust. Note that quitting (`q` on the main menu) terminates the process; since Xous apps are started at boot and the app menu only switches focus, the menu entry is dead until reboot (**Suspected**; same pattern in c64).

## Improvements (prioritised)
1. Fix O-1, add perft + differential tests to the core crate; delete the vacuous tests.
2. Wire the AI: worker thread + result message, iterative deepening with a wall-clock budget from `ticktimer.elapsed_ms()`, abort flag on background.
3. Fix the cfg gates and F-key codes; then actually exercise save/resume and stats.
4. Search efficiency before depth: O-8, a small transposition table (`Board::hash` is documented as "for transposition tables" but none exists, and the module doc's "iterative deepening" is not implemented either; the multiplicative hash is weak, use Zobrist), parity/fastest-first ordering in the solver, replace the per-square `calculate_flips` loop in `count_moves`/`legal_moves_bitboard` with the standard Kogge-Stone/dumb7fill mobility bitboard (`evaluate()` calls `count_moves` four times per leaf, `order_moves` once per move).
5. Non-determinism for Easy/Medium: pick randomly among near-equal root moves with the TRNG; today every game against a given level is identical.
6. UX: one-key pass acknowledgement, show whose colour the human is, confirm before New Game discards a game, partial redraw (only changed cells) instead of ~150 GAM calls per key.

# 2. C64 (`precursor-c64`)

**Verdict:** The 6502 core is genuinely good (passes Klaus Dormann's functional suite), and no copyrighted ROMs are bundled. Everything around it is a skeleton: nothing drives the emulation loop, loading a game never runs it, the app struct is ~3x the main-thread stack, and the README's screenshots show Shellchat rather than the app. **Health: 3.5/10** (CPU core alone: 8/10).

## 6502 correctness (verified on host)

| Area | Result |
|---|---|
| Legal opcodes | 151/151 have a match arm |
| Klaus Dormann functional test | **Pass** (reaches `$3469`) |
| BCD ADC/SBC, all 131,072 input triples incl. invalid BCD | Accumulator and carry match the NMOS reference exactly |
| BCD flags | ADC: Z differs in 104 and V in 672 valid-BCD cases (code derives Z from the BCD intermediate and V from the binary sum, `cpu.rs:206-210`; NMOS uses the binary sum for Z and the pre-fixup high nibble for V). SBC flags exact. Harmless for almost all software. |
| Stack wrap, JMP ($xxFF) bug, BRK/PHP B flag, RTI/PLP | Correct |
| Page-cross timing | Branch penalties modelled (`cpu.rs:192`); **no +1 cycle for abs,X / abs,Y / (zp),Y page crossings** (all fixed at base cycles, e.g. `cpu.rs:272-275`). Timer-relative timing drifts slightly. |
| RMW dummy write | Not modelled (`cpu.rs:539-589`); matters only for `INC/ASL $D019` IRQ acknowledge, and raster IRQs are not implemented anyway. |
| Interrupts | IRQ is delivered as an edge at timer underflow and dropped if I is set (`main.rs:409-411`, `cpu.rs:603-612`); real hardware is level-triggered until `$DC0D` is read. NMI exists but is never raised. |

# Cross-cutting patterns

1. **Docs and screenshots describe software that does not exist yet.** c64 screenshots are Shellchat; five Othello "gameplay" screenshots are the same frozen frame; README performance, feature and opcode tables in all three repos overstate the code. The capture pipeline should assert that the status bar reads "Running: <App>" and that successive frames differ, and READMEs should be generated from what tests demonstrate.
2. **Wrong `cfg` for the target.** `target_os = "none"` (Othello storage/feedback) never matches Xous. Grep the whole portfolio for `target_os = "none"` guarding real code (as opposed to the inert `cfg_attr(..., no_std)` boilerplate) and for `target_os = "xous"` on `no_std`/`no_main` (gameboy).
3. **Key codes are guessed per app.** F-keys appear as U+F001, U+0091 and U+0014 within this slice; arrows as U+2190 and U+F700. A shared `precursor-keys` constants crate (F1-F4 = U+0011-0014, arrows U+2190-2193, Menu U+2234, Enter `\r`, Backspace U+0008) would remove a whole class of dead-input bugs, and every screen needs a non-F-key way out.
4. **No time base.** Neither app that needs one (c64 frames, Othello AI) actually has a pump: one never creates it, the other never sends the message. A small shared "pump thread with start/stop on focus" helper is warranted (the toolkit notes describe one).
5. **Heavy work and blocking I/O on the event loop** (Othello search, c64 `accept()`), and **large state on a 32 KiB main-thread stack** (c64). Rule of thumb for the portfolio: anything over ~4 KB goes in a `Box`/`Vec`; anything over ~50 ms goes in a worker thread.
6. **Pure-logic cores are testable but under-tested.** `othello-core` proves the split works (tests run on host), yet its tests missed a rules bug that a 30-line perft would catch; `c64/cpu.rs` passes an industry conformance suite that is not checked in; `gameboy/cpu.rs` has no tests and two broken demos. Recommend: each emulator/engine core as its own crate with a conformance test (perft, Klaus, Blargg) in CI.
7. **TCP side channels** (`c64` import on 6464, Othello export on 7880, both `0.0.0.0`, blocking, unauthenticated, unbounded) are a questionable fit for a security-focused device; if kept, make them opt-in per use, time-limited, size-capped, and show the peer address for confirmation.
8. **Upstream drift is small here**: `destroy_server` -> `unsafe` in c64 and othello. The 44 gameboy errors are an invented API, not drift.
9. **Quit-by-terminate**: c64 and othello exit the process on `q`/F4; with boot-launched Xous apps this likely strands the app-menu entry until reboot (Suspected). Prefer returning focus over terminating.
